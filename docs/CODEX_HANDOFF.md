# Codex handoff

## 現在の入口

- 起動: `npm start`
- 入力: `../data/raw/`
- 実装: `src/`、`public/`
- 実装済み機能の診断: `scripts/diagnostics/`
- 未完成機能の実験: `scripts/experiments/`
- テスト: `npm run check && npm test`

## 動作済み

- 録画フォルダの5秒間隔監視
- 一覧で `待機中 / 確認中 / 分割中 / 分析中 / 分析済み / 失敗` を表示
- ルール表示とHUDから試合区間を検出し、音声付きMP4へ分割
- 分割済み動画の再利用
- HTTP Range対応の動画配信
- リザルトの黄色い自分マーカーとブキ画像から、自軍HUD上の本人枠を試合ごとに特定
- 特定した本人HUD枠だけを0.25秒刻みで追跡して自分のデスを検出
- 8人のHUDアイコンから1秒ごとの生存人数と人数差を生成
- 画面上部のゲームカウントを複数閾値の数字モデルで自動抽出
- デス直後などに開かれたステージマップ画面を自動抽出
- 動画、シークバー、デス帯、ゲームカウント、人数差グラフ、分析ポイントの同期
- 動画・マップ・分析の3面レビューと、ハンバーガーメニューからの録画一覧

## 基準録画

`2026-08-08 15-20-32.mp4` は4試合として検出済み。

| 試合 | 元録画区間 | 長さ | 自分のデス |
| --- | --- | --- | --- |
| 01 | 22〜404秒 | 382秒 | 10件 |
| 02 | 440〜736秒 | 296秒 | 7件 |
| 03 | 764〜1044秒 | 280秒 | 4件 |
| 04 | 1072〜1428秒 | 356秒 | 7件 |

解析JSONはバージョン5。本人HUD枠は順に2番、2番、2番、3番（人間向けの1始まり表記）としてリザルトから特定した。試合02は詳細リザルトが録画にないため、直前試合のリザルトブキ画像を照合している。人数推移は `gameFlow.playerCounts`、ゲームカウントは `gameFlow.gameCounts`、観測マップは `stageMap` に保存する。

## 次に実装するもの

1. 映像内で視認できた敵味方の検出、枠、ブキ名
2. 自分の試合全体の動線
3. 視認情報に基づく敵味方の短時間予想動線とステージマップ同期
4. 観測マップ画像とWikiのクリーンなステージ画像の自動照合

知覚できなかった敵味方の実位置は表示しない。観測値と予想値は解析JSONでもUIでも区別する。

ゲームカウントOCRは軽量な数字モデルを `src/game-count-model.json` に置き、製品パイプラインと画面へ接続済み。誤読はまだ残るため、観測値の時系列安定化と実録画ごとのQAを継続する。
