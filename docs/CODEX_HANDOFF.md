# Codex handoff

## 現在の入口

- 起動: `npm start`
- 入力: `../data/raw/`
- 実装: `src/`、`public/`
- 実装済み機能の診断: `scripts/diagnostics/`
- 未完成機能の実験: `scripts/experiments/`
- テスト: `npm run check && npm test`

## 動作済み

- 録画フォルダの5秒間隔監視
- 一覧で `待機中 / 確認中 / 分割中 / 分析中 / 分析済み / 失敗` を表示
- ルール表示とHUDから試合区間を検出し、音声付きMP4へ分割
- 分割済み動画の再利用
- HTTP Range対応の動画配信
- リザルトの黄色い自分マーカーとブキ画像から、自軍HUD上の本人枠を試合ごとに特定
- 特定した本人HUD枠と右下の「復活まであとX秒」をデスごとに照合し、両者の実測時間差を保存。HUD非表示時は復活UI初出へフォールバック
- リザルトのデス数と検出件数を照合し、人が確認した誤検出は自動観測と分離した回帰データとして保持
- 8人のHUDアイコンから1秒ごとの生存人数と人数差を生成
- 画面上部のゲームカウントを複数閾値の数字モデルで自動抽出
- デス直後などに開かれたステージマップ画面を自動抽出し、確認済みの `assets/stage-maps` 素材をレビュー画面に表示
- マップ画面の右上ギアパネル・左右プレイヤーパネル・中央マップ・ピンクカーソルを組み合わせて、位置候補を抽出
- 直接観測した位置、観測点間の低確度推定、過去2観測からの6秒予測を別データとして生成し、実線・破線・観測点で区別して表示
- 青い円環、ブキ形状、白い向き三角形から味方マーカーを抽出し、観測位置と向きに基づく6秒予測を表示
- デス直後に確認した自分位置を根拠に、敵の正確な座標を断定しない拡大式の脅威範囲を予測表示
- 本人デスと復活UIで確定したデスカメラ区間を、動画上の破線「敵候補」注目範囲として表示
- 動画、シークバー上のデスマーカー、ゲームカウント、人数差背景、分析ポイントの同期
- 動画・マップ・分析の3面レビューと、ハンバーガーメニューからの録画一覧

## 基準録画

`2026-08-08 15-20-32.mp4` は4試合として検出済み。

| 試合 | 元録画区間 | 長さ | リザルト | 現在の検出 |
| --- | --- | --- | --- | --- |
| 01 | 22〜404秒 | 382秒 | 9件 | 9件 |
| 02 | 440〜736秒 | 296秒 | 未検証 | 6件 |
| 03 | 764〜1044秒 | 280秒 | 未検証 | 9件 |
| 04 | 1072〜1428秒 | 356秒 | 未検証 | 7件 |

解析JSONはバージョン11。試合01の本人HUD枠は4番。00:33の本人デスはHUDで33.25秒、復活UIで35.25秒に検出し、2秒差で統合する。以前の30〜45秒の手動除外は本物のデスまで消していたため撤去済み。02:38の点滅誤検出を除外した状態で、リザルト9デスと検出9件が一致する。デスごとのHUD検出時刻、復活UI初出、時間差は `events[].evidence.timing`、人数推移は `gameFlow.playerCounts`、ゲームカウントは `gameFlow.gameCounts`、素材と観測根拠は `stageMap` に保存する。

空間解析は `spatial.observations`、`playerRoute`、`spatial.predictions` に保存する。基準録画の観測点数は試合01=5、試合02=2、試合03=1、試合04=0。試合01は観測5点、観測間推定を含む262点、短期予測3本。マップ画面が安定して確認できない試合04には座標を生成していない。現段階の自分位置はマップ描画が安定した最初のカーソル位置を候補とするため、確度を保持し、直接観測と推定をUIで区別する。

味方位置は `spatial.entityTracks` に保存する。基準録画では試合01=13観測、試合02=5観測、試合03=1観測、試合04=2観測。各観測から白い向き三角形の方向へ6秒の予測を生成する。敵位置はマップ画面だけでは知覚できないため未生成で、映像内観測との座標対応付けが次の対象。

敵については、デス後10秒以内に得た自分位置とデス事実を結び付けた `spatial.threatZones` を追加済み。これは敵の観測座標ではなく低確度予測であり、ピンクの拡大破線範囲として表示する。映像内で視認した敵の矩形検出と、カメラ姿勢を含むステージ座標変換は引き続き未実装。

動画側は `detections[].kind = death-camera-focus-candidate` を追加済み。敵個体の矩形ではなく、デスカメラが敵を捉える注目範囲なので破線表示にする。ブキ名は未特定であり `weapon: null`。通常戦闘中の敵個体検出、正確な矩形、ブキ名、カメラ姿勢を含む座標変換は引き続き未実装。

## 次に実装するもの

1. 映像内で視認できた敵味方の検出、枠、ブキ名
2. マップカーソル以外の根拠（自分アイコン・カメラ位置推定）を加え、自分の動線精度を上げる
3. 視認できた敵味方の画面座標をステージ座標へ対応付け、観測・短時間予想動線を追加する
4. 観測マップ画像とWikiのクリーンなステージ画像の自動照合

知覚できなかった敵味方の実位置は表示しない。観測値と予想値は解析JSONでもUIでも区別する。

ゲームカウントOCRは軽量な数字モデルを `src/game-count-model.json` に置き、製品パイプラインと画面へ接続済み。誤読はまだ残るため、観測値の時系列安定化と実録画ごとのQAを継続する。

## 既知の誤検出

- 試合01の02:38は本人デスではない。スペシャル使用中に本人HUDアイコンが青から白っぽく点滅し、内部の斜線が一時的に灰色の×判定を満たした。
- 原因だった `candidateRuns` の結合幅を5秒から0.5秒へ短縮し、0.25秒サンプリングで連続性のある×だけをHUDデスとして扱うよう修正済み。HUD非表示区間は復活UIのフォールバックで補う。
- 02:38候補が除去される回帰テストを追加済み。
