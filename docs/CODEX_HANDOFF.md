# Codex handoff

## 現在の入口

- 起動: `npm start`
- 入力: `../data/raw/`
- 実装: `src/`、`public/`
- 実装済み機能の診断: `scripts/diagnostics/`
- 未完成機能の実験: `scripts/experiments/`
- テスト: `npm run check && npm test`

## 動作済み

- 録画フォルダの5秒間隔監視
- 一覧で `待機中 / 確認中 / 分割中 / 分析中 / 分析済み / 失敗` を表示
- ルール表示とHUDから試合区間を検出し、音声付きMP4へ分割
- 分割済み動画の再利用
- HTTP Range対応の動画配信
- リザルトの黄色い自分マーカーとブキ画像から、自軍HUD上の本人枠を試合ごとに特定
- 特定した本人HUD枠と右下の「復活まであとX秒」をデスごとに照合し、両者の実測時間差を保存。HUD非表示時は復活UI初出へフォールバック
- リザルトのデス数と検出件数を照合し、人が確認した誤検出は自動観測と分離した回帰データとして保持
- 8人のHUDアイコンから1秒ごとの生存人数と人数差を生成
- 画面上部のゲームカウントを複数閾値の数字モデルで自動抽出
- デス直後などに開かれたステージマップ画面を自動抽出し、確認済みの `assets/stage-maps` 素材をレビュー画面に表示
- マップ画面の右上ギアパネル・左右プレイヤーパネル・中央マップを確認し、ピンク環を自分位置候補として抽出。味方マーカー中心から18px以内ならジャンプ先選択として除外
- 直接観測した位置、観測点間の低確度推定、過去2観測からの6秒予測を別データとして生成し、実線・破線・観測点で区別して表示
- 青い円環、ブキ形状、白い向き三角形から味方マーカーを抽出し、観測位置と向きに基づく6秒予測を表示
- デス直後に確認した自分位置を根拠に、敵の正確な座標を断定しない拡大式の脅威範囲を予測表示
- 本人デスと復活UIで確定したデスカメラ区間を、動画上の破線「敵候補」注目範囲として表示
- デス前4秒の相手色・形状・フレーム間の動きを0.5秒間隔で追跡し、2フレーム以上連続した領域を通常戦闘の低確度「敵候補」として表示
- 敵候補と自分の推定動線が同時刻にある場合、移動方向を仮のカメラ方向としてマップ上の広い不確実範囲と4秒予測を生成
- リザルトの自分行からブキ画像だけを切り出し、173種の日本語ブキ辞書へ照合して動画見出しに自分のブキ名を表示
- 動画、シークバー上のデスマーカー、ゲームカウント、人数差背景、分析ポイントの同期
- 動画・マップ・分析の3面レビューと、ハンバーガーメニューからの録画一覧

## 基準録画

`2026-08-08 15-20-32.mp4` は4試合として検出済み。

| 試合 | 元録画区間 | 長さ | リザルト | 現在の検出 |
| --- | --- | --- | --- | --- |
| 01 | 22〜404秒 | 382秒 | 9件 | 9件 |
| 02 | 440〜736秒 | 296秒 | 未検証 | 6件 |
| 03 | 764〜1044秒 | 280秒 | 未検証 | 9件 |
| 04 | 1072〜1428秒 | 356秒 | 未検証 | 7件 |

解析JSONはバージョン16。試合01の本人HUD枠は4番。00:33の本人デスはHUDで33.25秒、復活UIで35.25秒に検出し、2秒差で統合する。以前の30〜45秒の手動除外は本物のデスまで消していたため撤去済み。02:38の点滅誤検出を除外した状態で、リザルト9デスと検出9件が一致する。デスごとのHUD検出時刻、復活UI初出、時間差は `events[].evidence.timing`、人数推移は `gameFlow.playerCounts`、ゲームカウントは `gameFlow.gameCounts`、素材と観測根拠は `stageMap` に保存する。

空間解析は `spatial.observations`、`playerRoute`、`spatial.predictions` に保存する。実フレームの側面パネル接続線を照合した結果、青いマーカーは味方であり、ピンク環が自分位置候補だった。ピンク環が味方中心から18px以内なら、スーパージャンプ先を選択している状態として除外する。広いインク面との誤認を防ぐため、環と17〜23px外側の色比率差を0.3以上必須にする。基準録画の自分位置は試合01=4点（動線194点）、試合02=2点（動線157点）、試合03・04=0点。試合03で紫インクを拾っていた右上候補は外周検査で除外済み。

味方位置は `spatial.entityTracks` に保存する。青い円環付きマーカーはピンク環との近さにかかわらず味方トラックへ保持し、白い向き三角形の方向へ6秒の予測を生成する。固定されたスタート地点アイコンは時系列クラスタで除外する。基準録画の観測数は試合01=13、試合02=5、試合03=1、試合04=2。

敵については、デス後10秒以内に得た自分位置とデス事実を結び付けた `spatial.threatZones` を追加済み。これは敵の観測座標ではなく低確度予測であり、ピンクの拡大破線範囲として表示する。通常戦闘ではデス前4秒以内の相手色・形状・動きが連続する領域を `enemy-color-motion-candidate` として生成する。ただし相手インクとの混同余地があるため確定観測には昇格させず、カメラ姿勢を含むステージ座標変換にもまだ利用しない。

動画側は `detections[].kind = death-camera-focus-candidate` と `enemy-color-motion-candidate` を追加済み。どちらも破線表示にし、後者は0.5秒間隔で2フレーム以上続く色・形状・動きの候補だけを採用する。ブキ名は未特定であり `weapon: null`。敵個体の確定検出、正確な人物境界、ブキ名、カメラ姿勢を含む座標変換は引き続き未実装。

基準録画の通常戦闘候補数は試合01=9、試合02=5、試合03=9、試合04=6。いずれも本人デス前4秒だけを探索している。相手色のインクと人物を完全には分離できないため、UIとJSONの両方で「候補」とし、敵の確定観測・ブキ名・正確なマップ位置へは昇格させない。

自分の推定動線と時間が重なり、移動方向を計算できた敵候補からのマップ予測は試合01=3場面、試合02=3場面、試合03・04=0。自分位置根拠がない試合には生成しない。中心線、破線の予測点、時間とともに広がるピンクの不確実範囲を表示し、敵の観測位置とは区別する。

自分のブキは、試合01と04でリザルト画像から `14式竹筒銃・甲` を直接識別、試合03は録画内の同一候補で補強、リザルトを直接確認できなかった試合02は前試合からの推定として保存する。直接確認・録画内補強・前試合推定の状態は `playerIdentity.weapon.status` で区別する。

## 次に実装するもの

1. 通常戦闘の敵候補を人物として確定する分類器、味方検出、ブキ名
2. ピンク環の自分位置候補を側面プレイヤーパネルの接続線やデス・復活状態とさらに照合する
3. 実際のカメラ姿勢を推定して、敵候補の画面座標からステージ座標への対応精度を上げる
4. 観測マップ画像とWikiのクリーンなステージ画像の自動照合

知覚できなかった敵味方の実位置は表示しない。観測値と予想値は解析JSONでもUIでも区別する。

ゲームカウントOCRは軽量な数字モデルを `src/game-count-model.json` に置き、製品パイプラインと画面へ接続済み。誤読はまだ残るため、観測値の時系列安定化と実録画ごとのQAを継続する。

## 既知の誤検出

- 試合01の02:38は本人デスではない。スペシャル使用中に本人HUDアイコンが青から白っぽく点滅し、内部の斜線が一時的に灰色の×判定を満たした。
- 原因だった `candidateRuns` の結合幅を5秒から0.5秒へ短縮し、0.25秒サンプリングで連続性のある×だけをHUDデスとして扱うよう修正済み。HUD非表示区間は復活UIのフォールバックで補う。
- 02:38候補が除去される回帰テストを追加済み。
