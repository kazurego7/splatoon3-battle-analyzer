# R2で外出先の動画を再生する

ローカル・宅内LANでは元の動画を使い、Tailscaleなど外部からのアクセスではR2に転送したMP4を使います。動画のデータはスマホがR2から直接取得します。アプリ画面・分析データへの接続には、従来どおり自宅PCとTailscaleが必要です。

## 最初に設定すること

1. [Cloudflareの管理画面](https://dash.cloudflare.com/)でR2を有効にします。利用開始時に支払い方法の登録を求められる場合があります。
2. R2でこのアプリ専用のバケット（例：`splatoon-videos`）を作ります。ストレージクラスは **Standard**、管轄指定は標準のものを選びます。公開アクセス・`r2.dev`・独自ドメインは不要です。
3. R2のAPIトークン管理からトークンを作ります。権限は **Object Read & Write（オブジェクトの読み取りと書き込み）**、対象は作成したバケットだけにします。一般的なCloudflare APIトークンではなく、R2の **Access Key ID / Secret Access Key** を使います。
4. 自宅PCでアプリを最新版で起動し、[クラウド動画の設定](http://localhost:4310/cloud.html)を開きます。アカウントID・バケット名・2つのキーを入力して「接続して自動転送を開始」を押します。キーの入力と再試行はlocalhostからのみ可能です。
5. 既存の試合と新しく追加した試合が順番に転送されます。まず1試合が「クラウドで再生できます」になるのを待ちます。
6. スマホでTailscaleを有効にして、`https://<このPC名>.<tailnet>.ts.net/sba/` を開き、完了した試合を再生して途中にシークしてください。自宅PCでも再生先を「クラウド動画」に変更すると確認できます。

キーはPC内の `data/app/r2/config.json` に保存され、Gitや画面の状態APIには出ません。チャットに貼る必要はありません。Windowsではこのファイルへのアクセス権はPCのユーザーフォルダの権限に従います。

## 再生先と完了状態

- `localhost`・宅内のプライベートIPv4・`.local`：ローカル動画を優先。ローカルで再生できれば完了です。
- TailscaleのIP・`.ts.net`など：R2を使用。MP4の転送後、R2から部分読み出しを確認してから完了です。転送途中に自宅の動画へ自動で戻しません。
- 自宅でもTailscaleのURLを使う場合など、URLから実際の回線を判別できないケースは設定画面の「この端末の再生先」で切り替えてください。回線速度を自動測定する機能はありません。
- 今のネイティブ動画プレイヤーで再生・シーク・拡大・デス分析の動画ループが使えます。YouTubeのロゴや追加操作は入りません。

MP4はH.264・最大720p・30fps・AAC音声・先頭に再生情報を配置した形式です。スマホの互換性を優先した1種類のクラウド用動画だけを置きます。長い録画を丸ごと転送せず、試合区間だけを作成します。

## 無料枠と容量

2026-09-12確認：R2 Standardの無料枠は保存10GB-month、Class A操作100万回/月、Class B操作1,000万回/月です。外向き転送量は無料です。詳しくは[公式料金表](https://developers.cloudflare.com/r2/pricing/)を確認してください。

アプリは**専用バケットの完了済みファイルと未完了アップロードの合計**を確認し、次の動画で8,000,000,000バイトを超える場合、その動画の転送を停止します。小さい別の試合が収まる場合は先に転送します。自動削除はありません。R2側で不要なクラウド動画を整理して、設定画面の「再試行」を押してください。ローカル原本は消しません。

完了済みの動画は約6時間ごとに再確認します。R2側で削除した動画は「削除されています」に切り替わり、自動では再転送しません。必要な試合だけ「再試行」で戻せます。

この制限はCloudflareの請求上限ではありません。他のバケット・アプリの利用量や操作回数、過去の月内保存量も無料枠に関係します。同じバケットへ別のアプリから同時に書き込む運用は避けてください。以前の概算約6GBは目安で、実際の変換後サイズを見ながら停止します。

## 接続が切れたとき

設定画面の「転送を一時停止」「転送を再開」で、R2への自動転送を止めたり再開したりできます。自宅PC・Tailscaleのどちらからでも操作できます。停止は送信中の通信にも反映され、アプリやPCを再起動しても維持されます。ローカル再生と、すでにR2へ転送済みの動画の再生は続けられます。

再開時は転送済みのパートを再利用します。停止した瞬間に送信中だったパートだけは再送する場合があります。動画の変換処理中に停止した場合、変換は最後まで進めますが、転送は開始しません。

8MiB単位で転送し、進行状況をPCに保存します。通信失敗時は間隔を空けて自動再試行し、PCを再起動してもR2側に残る転送済みパートから再開します。転送完了の応答が途切れた場合も、R2上のファイルを確認して重複転送を避けます。R2側の未完了アップロードが期限切れになった場合は再送します。

署名付きURLの有効期限は24時間です。再生URLはアプリが発行するため、バケットを公開する必要はありません。期限切れによる読み込みエラー時はURLを更新し、再生位置を戻します。URLを知っている人は期限内にその動画を再生できます。

通常のネイティブ動画再生ではCORS設定は必須ではありません。このアプリは動画に`crossorigin`を付けずに再生します。今後、動画フレームを別途取得する処理を追加する場合は、[R2のCORS設定](https://developers.cloudflare.com/r2/buckets/cors/)でアプリの実際のオリジンを指定し、GET/HEAD、Rangeを許可してください。

旧YouTube自動投稿処理はアプリから取り除きました。以前の認証データやYouTube上の動画を削除する処理は行いません。
