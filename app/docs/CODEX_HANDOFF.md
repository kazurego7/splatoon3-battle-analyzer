# Codex handoff

## 現在の入口

- 起動: `npm start`
- 入力: `../data/raw/`
- 実装: `src/`、`public/`
- 実装済み機能の診断: `scripts/diagnostics/`
- 未完成機能の実験: `scripts/experiments/`
- テスト: `npm run check && npm test`

## 動作済み

- 録画フォルダの5秒間隔監視
- 一覧で `待機中 / 確認中 / 分割中 / 分析中 / 分析済み / 失敗` を表示
- ルール表示とHUDから試合区間を検出し、音声付きMP4へ分割
- 分割済み動画の再利用
- HTTP Range対応の動画配信
- リザルトの黄色い自分マーカーとブキ画像から、自軍HUD上の本人枠を試合ごとに特定
- 特定した本人HUD枠と右下の「復活まであとX秒」をデスごとに照合し、両者の実測時間差を保存。HUD非表示時は復活UI初出へフォールバック
- 詳細リザルトまたは個人戦績画面のデス数をローカルOCRで読み、検出件数と照合。人が確認した誤検出は自動観測と分離した回帰データとして保持
- 8人のHUDアイコンから1秒ごとの生存人数と人数差を生成
- 画面上部のゲームカウントを複数閾値の数字モデルで自動抽出
- デス直後などに開かれたステージマップ画面を自動抽出し、確認済みの `assets/stage-maps` 素材をレビュー画面に表示
- マップ画面の左上にある閉じる×の固定位置まで照合し、通常戦闘のHUDをマップ画面から除外
- 左下の本人パネルから試合ごとの自軍色を推定し、同色の円環・内部形状・白い向き三角形から味方候補を抽出
- 側面パネルのピンク選択枠とジャンプ用カーソルを組み合わせ、選択中の味方位置を直接観測として保存
- 自分専用マーカーを確定できた場合だけ、観測点・観測間推定・短期予測を別データとして生成する構造を用意
- デス直後に確認した自分位置を根拠に、敵の正確な座標を断定しない拡大式の脅威範囲を予測表示
- 本人デスと復活UIで確定したデスカメラ区間を、デス説明用の内部根拠として保存
- デス前4秒の相手色・形状・フレーム間の動きを0.5秒間隔で追跡し、2フレーム以上連続した領域を内部の低確度候補として保存
- 敵候補と自分の推定動線が同時刻にある場合、移動方向を仮のカメラ方向としてマップ上の広い不確実範囲と4秒予測を生成
- リザルトの自分行からブキ画像だけを切り出し、173種の日本語ブキ辞書へ照合して動画見出しに自分のブキ名を表示
- 動画、シークバー上のデスマーカー、ゲームカウント、人数差背景、デス分析の同期
- デス前8秒から直後までの6コマをChatGPTプランで認証したCodex CLIへ渡し、行動シーケンス・分岐点・反復パターンと、その根拠となる複数の再生範囲を構造化して保存
- 同じ動画とデス時刻のAI分析結果を再利用し、プラン上限・未ログイン・一時エラー時はローカル説明へ自動フォールバック
- 試合画面は動画・マップ・デス分析をスクロールなしで見渡せる3面構成とし、戻るボタンで録画一覧へ移動
- 反復パターンは別ウィンドウの俯瞰レポートへ分離し、パターンごとに独立した動画で複数範囲のループ再生と通常再生を切り替え

## 基準録画

`2026-08-08 15-20-32.mp4` は4試合として検出済み。

| 試合 | 元録画区間 | 長さ | リザルト | 現在の検出 |
| --- | --- | --- | --- | --- |
| 01 | 22〜404秒 | 382秒 | 9件 | 9件 |
| 02 | 440〜736秒 | 296秒 | 未検証 | 6件 |
| 03 | 764〜1044秒 | 280秒 | 未検証 | 9件 |
| 04 | 1072〜1428秒 | 356秒 | 未検証 | 7件 |

解析JSONはバージョン26。試合01の本人HUD枠は4番。00:33の本人デスはHUDで33.25秒、復活UIで35.25秒に検出し、2秒差で統合する。以前の30〜45秒の手動除外は本物のデスまで消していたため撤去済み。02:38の点滅誤検出を除外した状態で、リザルト9デスと検出9件が一致する。デスごとのHUD検出時刻、復活UI初出、時間差は `events[].evidence.timing`、人数推移は `gameFlow.playerCounts`、素材と観測根拠は `stageMap` に保存する。

空間解析は `spatial.observations`、`playerRoute`、`spatial.predictions` に保存する。マップ上の円はスティックで動かせるスーパージャンプ用カーソルであり、自分位置ではないためv16までの自分動線を撤回した。基準録画では自分専用マーカーをまだ確定できず、自分位置・動線・それを根拠にした敵マップ予測は0件とする。

味方位置は `spatial.entityTracks` に保存する。自軍色は左下の本人パネルから推定し、青・橙・黄など試合ごとの色へ対応する。上・左・右のプレイヤーパネルから伸びる白／ピンクの点線がマーカー付近まで続くことを確認した位置だけを味方観測へ昇格する。ピンク選択枠とカーソルを同時に確認できた場合も、選択中の味方位置として保存する。固定されたスタート地点アイコンは時系列クラスタで除外する。味方アイコン周囲の小さな矢印はD-pad割当であり移動方向ではないため、v18ではこれを根拠とした予測を撤回した。

v18再解析後の味方トラック数／観測フレーム数は、試合01=3/8、試合02=3/8、試合03=3/6、試合04=4/6。D-pad矢印を使った味方予測は全試合0件。全試合で自分位置・自分動線・それを根拠にした敵マップ予測も0件。

敵については、デス後10秒以内に得た自分位置とデス事実を結び付けた `spatial.threatZones` を追加済み。これは敵の観測座標ではなく低確度予測であり、ピンクの拡大破線範囲として表示する。通常戦闘ではデス前4秒以内の相手色・形状・動きが連続する領域を `enemy-color-motion-candidate` として生成する。ただし相手インクとの混同余地があるため確定観測には昇格させず、カメラ姿勢を含むステージ座標変換にもまだ利用しない。

内部根拠として `detections[].kind = death-camera-focus-candidate` と `enemy-color-motion-candidate` を保存する。動画上には表示せず、後者は0.5秒間隔で2フレーム以上続く色・形状・動きの候補だけを採用する。ブキ名は未特定であり `weapon: null`。敵個体の確定検出、正確な人物境界、ブキ名、カメラ姿勢を含む座標変換は引き続き未実装。

基準録画の通常戦闘候補数は試合01=9、試合02=5、試合03=9、試合04=6。いずれも本人デス前4秒だけを探索している。相手色のインクと人物を完全には分離できないため、JSON内部の「候補」に留め、UI表示、敵の確定観測、ブキ名、正確なマップ位置へは昇格させない。

自分の推定動線を根拠にする敵マップ予測の構造は残すが、v17では自分位置を確定できていないため全試合0件とする。中心線や不確実範囲は、根拠が得られた場合だけ敵の観測位置と区別して表示する。

自分のブキは、試合01と04でリザルト画像から `14式竹筒銃・甲` を直接識別、試合03は録画内の同一候補で補強、リザルトを直接確認できなかった試合02は前試合からの推定として保存する。直接確認・録画内補強・前試合推定の状態は `playerIdentity.weapon.status` で区別する。

## 次に実装するもの

1. 通常戦闘の敵候補を人物として確定する分類器、味方検出、ブキ名
2. マップを開いてカーソルを動かしていない正解動画と位置ラベルを使い、自分位置を初期カーソルまたは映像地物から確定できるか検証する
3. 実際のカメラ姿勢を推定して、敵候補の画面座標からステージ座標への対応精度を上げる
4. 観測マップ画像とWikiのクリーンなステージ画像の自動照合

知覚できなかった敵味方の実位置は表示しない。観測値と予想値は解析JSONでもUIでも区別する。

ゲームカウントOCRは軽量な数字モデルを `src/game-count-model.json` に置き、製品パイプラインと画面へ接続済み。誤読はまだ残るため、観測値の時系列安定化と実録画ごとのQAを継続する。

## 既知の誤検出

- 試合01の02:38は本人デスではない。スペシャル使用中に本人HUDアイコンが青から白っぽく点滅し、内部の斜線が一時的に灰色の×判定を満たした。
- 原因だった `candidateRuns` の結合幅を5秒から0.5秒へ短縮し、0.25秒サンプリングで連続性のある×だけをHUDデスとして扱うよう修正済み。HUD非表示区間は復活UIのフォールバックで補う。
- 02:38候補が除去される回帰テストを追加済み。
