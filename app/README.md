# splatoon3-battle-analyzer App

キャプチャーボードの長時間録画を録画中から読み、試合区間の検出、基礎解析、個人リザルト直後の再生までをローカルで自動実行するWebアプリです。分析には元画質を使い、録画中だけ720pの軽量な再生用断片を作ります。

## 起動

必要なものは Node.js 22 以上とFFmpegです。FFmpegは環境変数 `FFMPEG_PATH` で実行ファイルを指定します。手元の `../tools/runtime/video-split/` に配置した場合は自動検出しますが、実行環境はGitHubリポジトリに含まれません。AIデス分析を使う場合は、npm依存関係として導入されるCodex CLIへChatGPTアカウントでログインします。

```powershell
cd app
npx codex login
npm start
```

ブラウザで <http://127.0.0.1:4310> を開きます。起動中にOBSのHybrid MP4録画を始めると、OBSプロファイルから保存先を自動検出し、通常5〜10秒以内に録画中分析が始まります。`../data/raw/` への手動追加も利用できます。

Tailscale内の別端末から使う場合は、Tailscaleを起動・ログインした状態で次を使います。

```powershell
npm run start:tailscale
```

起動時に表示される `https://<このPC名>.<tailnet>.ts.net/sba/` がリモート用URLです。`/sba` だけをこのアプリに割り当て、既存のトップページや他アプリの設定を維持します。Tailscale Serveがローカルの4310番へ安全に中継するため、WindowsのLAN側へポートを公開する必要はありません。アクセスする端末でも同じtailnetのTailscaleを有効にしてください。`http://<Tailscale IP>:4310` は使用しません。

ローカル・宅内LANでは元動画を優先します。Tailscaleなど外部からのアクセスではR2への転送・読み出し確認ができた試合だけ完了扱いにします。初回はメニューの「クラウド動画」から設定してください。旧ネットワーク用動画の生成コマンドは残していますが、リモート再生の自動フォールバックには使用しません。

## 処理の流れ

1. 録画を一覧へ登録する
2. 映像・音声・コーデックを確認する
3. 2秒間隔の映像特徴とルール表示から試合区間を検出する
4. 個人リザルトまで含め、入力と同じ映像コーデックで一時領域へ全試合を再エンコードする
5. 全クリップの映像・音声を確認してから完成領域へ入れ替える
6. 試合終了後の左上に表示される `WIN!` / `LOSE...` を複数フレームで確認し、勝敗を判定する
7. リザルトの自分行または個人戦績画面から、追加料金のないローカルOCRでデス数を読み、本人HUD枠と復活UIの候補をその件数へ照合する。リザルトがなければデス分析を生成しない
8. 必要に応じて分析画面のボタンから、認証済みのCodex CLIで試合動画と事前分析データをAstra自身が調査し、試合内で繰り返す失敗パターンを抽出する。`CODEX_DEATH_ANALYSIS=true` の場合は初回解析時にも自動実行する
9. 一覧を「分析済み」にし、各試合を開けるようにする

録画中は `分析中` と表示し、個人リザルトを安定検出した試合から順に開けるようにします。ブラウザは約2秒単位の断片を連続動画として再生します。録画終了後は断片をすべて削除し、元録画の該当時刻を直接再生します。OBSの元録画は後日の再分析用にそのまま保持します。

試合画面のデス分析は、未分析時にはレポートダイジェスト欄の中央に分析内容の説明と大きな `AI分析を実行する！` ボタンを表示し、分析後は失敗パターンを1〜2文にまとめたダイジェストと `俯瞰レポート` ボタンへ切り替えます。分析中に一覧へ戻っても、同じ試合を開き直すと進行中表示を復元します。その下には時刻とデス内容だけの縦一覧を表示します。一覧はスクロールでき、項目を選ぶと映像の8秒前へ移動します。長い反復パターン分析は「俯瞰レポート」で別ウィンドウに開きます。各パターンは独立した動画プレイヤーを持ち、AIが選んだ複数の根拠範囲を順にループする `クリップループ` と、元動画を制限なく見る `通常再生` を個別に切り替えられます。時系列グラフへカーソルを合わせると、その時刻の味方・相手カウントとペナルティをグラフ下部へ表示します。動画下の時刻・カウント・人数差は固定幅で配置します。

## コマンド

```powershell
# 特定の録画を手動で再分析
npm run analyze -- "2026-08-08 15-20-32.mp4"

# 区間検出だけを調査
npm run inspect -- "..\data\raw\2026-08-08 15-20-32.mp4"

# 分割済み1試合のデス検出を確認
npm run inspect:deaths -- "..\data\matches\<recording-id>\match-01.mp4" 342

# 敵味方の生存人数検出を確認
npm run inspect:counts -- "..\data\matches\<recording-id>\match-01.mp4" 342

# AI分析などを保持したまま、既存録画の生存人数だけを再計算
npm run refresh:player-counts -- "2026-08-09 15-29-11.mp4"

# AI分析などを保持したまま、既存録画のマップ表示判定とグラフを再計算
npm run refresh:map-detection -- "2026-08-09 15-29-11.mp4"

# リザルトからの本人HUD枠特定を確認
npm run inspect:identity -- "..\data\matches\<recording-id>\match-01.mp4"

# 確認済みラベルからペナルティ数字モデルを再生成
npm run calibrate:game-penalty

# ヤグラ・ホコの移動マーカー用数字モデルを再生成
npm run calibrate:objective-count

# ルール別のカウント時系列を0.5秒間隔で確認
npm run inspect:rule-count -- "..\data\matches\<recording-id>\match-01.mp4" "ヤグラ" 371 340

# 未学習時刻のラベル一致・短い値往復・マップ表示時変化を検証
npm run validate:game-penalty

# 人が確認した勝敗ラベルと終了後のWIN/LOSE発表判定を照合
npm run validate:outcomes -- "..\data\raw\<recording>.mp4" "..\data\work\<recording-id>\manifest.json"

# 構文・ユニットテスト
npm run check
npm test
npm run check:public

```

ペナルティ教師ラベルは `config/game-penalty-calibration-observations.json`、未学習時刻の検証ラベルは `config/game-penalty-validation-observations.json` に保存します。各観測は `[試合内秒数, 自軍ペナルティ, 相手ペナルティ]` で、表示されていない側は `null` です。確認用の切り抜きとコンタクトシートは `../data/work/penalty-training-review/` と `../data/work/penalty-validation-review/` にあります。

ゲームカウントはルール別にHUDを切り替えます。エリアとアサリはイカランプ直下の固定スコアカードを読み、カウント下の `+N` もペナルティとして保存します。ヤグラとホコは進行線上を左右へ移動する丸いカウントマーカーを広い範囲から追跡し、数値ペナルティは存在しないため常に0として扱います。ヤグラ・ホコ用の確認済み数字は `config/game-count-objective-calibration-observations.json` に保存します。

勝敗の確認済みラベルは `config/outcome-validation-observations.json` に保存します。録画や勝敗発表画像はGitへ含めず、検証コマンドへローカル録画と区間マニフェストを渡します。

環境変数:

- `PORT`: HTTPポート。既定値は `4310`
- `HOST`: HTTP待受アドレス。既定値は安全な `127.0.0.1`。通常、Tailscale利用時は変更せずServe経由にする
- `AUTO_PROCESS=false`: 自動キュー処理を止め、既存結果の確認だけを行う
- `FFMPEG_PATH`: 使用するFFmpeg実行ファイルを明示する
- `CODEX_DEATH_ANALYSIS=true`: 初回解析時にもAIシーケンス分析を自動実行する（既定は画面からの手動実行のみ）
- `CODEX_DEATH_MODEL`: デス分析に使うOpenAIモデルを明示する（既定は `gpt-6-astra`。推論の強度は「中」`medium`）
- `CODEX_DEATH_TIMEOUT_MS`: Codex実行を強制終了する待ち時間。既定は無効で、運用上どうしても上限が必要な場合だけ指定します
- `CODEX_DEATH_ANALYSIS_REFRESH=true`: 同じ動画・デス時刻の保存済みCodex結果も再生成する

リザルトのデス数読取は常にローカルで完結し、CodexやOpenAI APIを呼びません。AIシーケンス分析は、画面で実行した場合、または `CODEX_DEATH_ANALYSIS=true` を明示した場合だけ、Codex CLIへ **ChatGPTアカウントでログインしている場合に限って** 実行します。`npx codex login status` で状態を確認できます。親プロセスに `OPENAI_API_KEY` が設定されていても解析プロセスへ渡さないため、OpenAI APIの従量課金へ自動で切り替わることはありません。ChatGPTプランの利用上限へ達した自動分析は、ローカル判定結果へフォールバックします。画面からの実行時はエラー理由を表示します。

画面のAI分析ボタンを1回押すと、全デスのシーケンス分析と俯瞰レポート生成を続けて実行します。固定タイムアウトは既定で使わず、Codexが完了またはエラーを返すまで待ちます。デス一覧が完成した時点で先に画面へ反映し、そのままレポート生成へ進みます。レポート完成後も画面へ自動反映されます。Codexから利用上限・認証・通信などのエラーが返された場合は原因別の対処を表示し、保存済みの生成物から再開できます。

## データ配置

- 入力録画: OBSで設定した録画先、または `../data/raw/`
- ローカル再生・解析: 元動画＋試合の開始・終了時刻（旧分割動画は移行時に削除しません）
- 録画中の再生用断片: `../data/live-media/<recording-id>/`
- ネットワーク用動画: `../data/remote-matches/<codec>/<recording-id>/`
- 状態: `../data/app/state.json`
- 解析JSON: `../data/app/analysis/<recording-id>/`
- サムネイル: `../data/app/thumbnails/<recording-id>/`
- 一時ファイル・検出キャッシュ: `../data/work/<recording-id>/`

データ形式は [ANALYSIS_SCHEMA.md](./docs/ANALYSIS_SCHEMA.md)、体験全体の方針は [PRODUCT_BRIEF.md](./docs/PRODUCT_BRIEF.md) を参照してください。横断分析の味方・相手ブキは、GO後から最初のデス前までの画面上部HUDを2フレーム照合して取得します。

`scripts/diagnostics/` は実装済み解析の確認用、`scripts/experiments/` は未完成機能の検証用です。アプリの通常利用では直接実行する必要はありません。

## 現在の解析範囲

ブキ名照合と検索アイコンには `npm run sync:icons` で生成するGit管理外の `src/weapon-catalog.json`、`../assets/weapon-icons/images/`、`../assets/rule-icons/images/` が必要です。クリーンなステージ表示にはGit管理外の `../assets/stage-maps/images/` が必要です。未導入でもアプリは起動し、該当する任意機能だけが無効になります。第三者データの扱いは [`docs/THIRD_PARTY_DATA.md`](docs/THIRD_PARTY_DATA.md) を確認してください。

実装済みなのは、自動試合分割、実動画再生、リザルトからの本人HUD枠特定と自分のブキ名照合、上部HUDと右下の復活カウントUIを使ったデス時刻照合、デス前8秒から直後までのAIシーケンス分析と反復パターン抽出、敵味方の生存人数と人数差、ゲームカウント、映像内マップ画面の抽出、`../assets/stage-maps/` のステージ素材表示、動画・シークバー・グラフ・マップの同期、味方位置の観測です。本人HUD枠は固定座標で決めず、リザルトの自分行に表示されたブキ画像を4つの自軍HUDアイコンへ照合します。自分のブキ名は同じリザルト画像を173種の日本語辞書へ照合し、確度不足の候補は画面に出しません。マップ画面は、画面下中央の「スタート地点」ボタンにある固定の循環矢印を主判定にし、左上の閉じるボタンと中央のマップ形状も組み合わせます。開閉中に固定UIが一瞬消えるフレームは前後の確定フレームから補います。自軍色は左下の本人パネルから試合ごとに推定し、味方は上・左・右のプレイヤーパネルから伸びる点線との接続まで確認できたマーカーだけを採用します。マップ上の円はスティックで動かせるジャンプ用カーソルなので自分位置には使わず、側面パネルがピンク枠なら選択中の味方位置として扱います。味方マーカー周囲の小さな矢印はD-padの割当表示であり進行方向ではないため、そこから予測動線は生成しません。自分専用マーカーは未検出のため、現時点では自分の動線を生成しません。デス時刻は両UIの早い検出を採用し、上部HUDが隠れている場合は復活UIの初出へフォールバックします。デス直前の相手色・形状・動きはデス説明とマップ予測の内部根拠に限り、動画上へ敵候補枠は表示しません。敵味方の確定検出、敵のブキ名、実カメラ姿勢による正確な座標対応は未完成のため、観測と予測を分離する方針です。モックは `../mock/` に参照用として保存しています。


### AIによる動画の自律調査

AI分析はAstra（推論「中」・`medium`）が試合全体を調べる方式です。固定画像の添付は行いません。専用の作業場所に動画の場所・時間軸の説明・事前分析JSON・画像抽出ツールを用意します。人数とカウントの推移、デス検出の根拠、ブキ、勝敗、ステージなど、保存済みのデータを読み、Astraが時刻・区間・抽出間隔・解像度・拡大範囲を決めて映像を調べます。レポート生成時にも同じ資料と画像を参照できます。

動画は選んだ時刻の画像を取り出して閲覧する仕組みです。音声を直接聴く機能はありません。事前分析を正解とは扱わず、映像との不一致や判定できない点を明記するよう指示しています。結果の時刻はデスに対する相対秒で、従来の固定6時点には限定しません。

作業場所はOSの一時フォルダに作成し、元動画は読み取り用の参照として渡します。`data/work/<録画ID>/codex-deaths/match-XX/workspace.json` に作業場所を記録します。そこに `context.json`、`preanalysis.json`、`inspections.jsonl`（抽出時刻・画像パス）、`sequence-events.jsonl` と `report-events.jsonl`（実行イベント）が残ります。一時フォルダの清掃でこれらの調査資料が消える場合がありますが、完成レポートは従来どおりアプリ側に保存します。

Codexは読み取り専用で起動し、ChatGPTログインを利用します。専用の `match_video.inspect_match` ツールが対象動画を読み、作業場所に画像を抽出し、その画像を直接Astraへ返します。シェル操作は必要ありません。1回のツール呼び出しで最大12枚、追加呼び出しで別の場面を調査できます。ユーザーのCodex設定は読み込まず、このツールを明示して起動します。旧方式の固定画像キャッシュは新方式に流用しません。モデル・事前分析データが変わるとキャッシュも更新されます。

レポート本文は敗因につながる行動とその影響に絞り、画面に表示済みの試合情報の列挙や分析手順・内部仕様を含めません。本文のデス参照は「デス1回目」などに整え、機械処理用IDとクリップの時刻は保持します。

## 録画終了後の詳細補完

録画中の簡易解析でステージ・ルール・自分のブキ・編成が欠けた場合は、録画終了後にバックグラウンドで自動補完します。リザルト検出から1.5秒後（試合区間の終端を超えない範囲）を読み、カードの表示途中を避けます。リザルトは確信度0.9以上、編成は既存の2画像照合で確定した結果だけ採用します。元動画、区間、K/D、デス解析は維持します。

未確定・失敗時は1時間以上空けて最大3回まで自動再試行します。状態は解析JSONの `detailEnrichment` に保存します。推測や目視による手入力で不足項目を埋めず、自動解析の改善で対処します。

## R2でのリモート再生

外出先はR2、ローカル・宅内LANはローカル動画を優先します。既存・新規の試合をバックグラウンドで自動転送し、リモートではR2から読み出せるまで準備中と表示します。容量8GBを超える転送は停止し、原本は保持します。メニューの「クラウド動画」で接続設定・進行状況・再試行・端末の再生先を管理できます。初回設定は [R2_SETUP.md](R2_SETUP.md) を参照してください。

## 試合動画の管理

録画済み取り込みも録画中の監視も、試合は元動画と開始・終了時刻で管理します。ローカル再生、画像抽出、AI分析はその区間を直接読み、デス・シーク・レポートの時刻は試合開始を0秒とします。R2転送時だけ試合ごとの720p軽量動画を生成します。録画中の一時的な映像断片は録画終了後に片づけます。

起動時に既存の完了済み試合を移行し、解析結果とR2の転送済み／転送途中の識別情報を維持します。移行前の一覧はdata/app/state.before-source-ranges.jsonに保存し、旧分割動画を自動削除しません。元動画を移動・削除するとローカル再生と解析ができなくなるため、元動画を保持してください。
